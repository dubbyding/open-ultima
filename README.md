# Open Ultima

An open-source, offline-first companion app for **Ultima earbuds** and **Ultima smartwatches**, built with Expo / React Native. It replaces the official *Ultima Link* (earbuds) and *ULTIMA Fit* (watch) apps with one app: no ads, no account, no cloud. Everything talks to the devices directly over Bluetooth, and your data stays on the phone unless you choose to export it.

Package / bundle ID: `com.nhumark.openultima`

Protocol details and how they were derived are in [REVERSE_ENGINEERING.md](REVERSE_ENGINEERING.md).

## Features

**Earbuds** (Jieli RCSP and Bluetrum ABMate chips)
- Battery (left, right, case), noise control (off / noise cancelling / aware), low-latency mode
- Equalizer: Ultima Signature/Balance presets and custom 10-band EQ
- Touch controls per earbud, filtered to the gestures and actions your model supports
- Find my earbuds (loud tone through the earbuds), rename, firmware info
- Pairs with earbuds already connected in Android Bluetooth settings

**Watch** (CRREPA / MOY `0xFEEA` protocol)
- Steps, distance, calories, sleep stages, all-day heart rate, SpO₂, blood pressure, stress
- On-demand heart rate / SpO₂ / blood pressure measurements
- Alarms, notifications, movement reminder, all-day heart-rate interval, watch settings
- Watch GPS workouts sync
- Calls: choose which device answers call audio (Android 12+)

**Workouts**
- Record runs, walks, rides and hikes with the **phone's GPS** (works whether or not the watch has GPS), with the screen locked
- Live distance, time, pace/speed, elevation gain; heart rate when the watch reports it
- Workout detail: route map, splits per km, elevation profile, GPX export
- Maps: OpenStreetMap (default, no key) or Google Maps

**Data**
- Everything stored locally (SQLite / AsyncStorage); JSON/CSV backup and restore
- **Health Connect** (Android) and **Apple Health** (iOS) sync
- **Google Sheets** export: one spreadsheet in your Drive, one tab per table, updated automatically (one-way, phone → sheet)
- Background keep-alive and auto-reconnect

## Requirements

- Node.js 22+ (tests use Node's built-in TypeScript stripping)
- Android: Android Studio / SDK, a phone on **Android 8.0+** (Health Connect needs it). Health Connect itself is built into Android 14+; install it from the Play Store on older versions.
- iOS: a Mac with Xcode and an Apple developer account
- A real device — Bluetooth doesn't work in emulators/simulators

## Getting started

```bash
npm install
cp .env.example .env          # optional, see Configuration
npx expo run:android          # builds the dev client and installs it
# or: npx expo run:ios --device
```

After the first native build, day-to-day JS work only needs Metro:

```bash
npx expo start
```

Native changes (new native packages, `app.json` / `app.config.js`, or `(rebuild)` variables in `.env`) need `npx expo run:android` again. The `android/` and `ios/` folders are generated by `npx expo prebuild` and are not committed.

> **Xiaomi / MIUI:** turn on *Developer options → Install via USB* and approve the prompt on the phone, or installs fail with `INSTALL_FAILED_USER_RESTRICTED`.

## Configuration

All settings are optional and live in `.env` (see [.env.example](.env.example) for the full list). `(rebuild)` means the value is baked into the native app.

| Variable | Purpose |
|---|---|
| `EXPO_PUBLIC_MAP_PROVIDER` | `osm` (default) or `google` |
| `EXPO_PUBLIC_GOOGLE_MAPS_API_KEY` | Google Maps key for Android, used with `google` (rebuild) |
| `EXPO_PUBLIC_OSM_TILE_URL` | Custom OSM-style tile server, `{z}/{x}/{y}` template |
| `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` | iOS OAuth client for Google Sheets sign-in (rebuild) |
| `EXPO_PUBLIC_STRAVA_CLIENT_ID` / `_SECRET` | Strava upload (parked — Strava's API now requires a paid subscription) |

### Maps

| `EXPO_PUBLIC_MAP_PROVIDER` | Android | iPhone | Key |
|---|---|---|---|
| `osm` | OpenStreetMap via MapLibre | OpenStreetMap via MapLibre | none |
| `google` | Google Maps | Apple Maps | Android only |

Google Maps' mobile SDK is free with no usage cap, but Google Cloud still requires a billing account; set a small budget alert.

### Google Cloud setup (Google Maps and Sheets)

1. Create a project at [console.cloud.google.com](https://console.cloud.google.com). Link billing (needed for Maps only) and add a budget alert.
2. **APIs & Services → Library:** enable **Google Sheets API**, and **Maps SDK for Android** if you use Google Maps.
3. **Maps key** (Android, optional): *Credentials → Create credentials → API key*, restrict it to *Android apps* with package `com.nhumark.openultima` + your SHA-1, and to the Maps SDK for Android API. Put it in `EXPO_PUBLIC_GOOGLE_MAPS_API_KEY`.
4. **Google Auth Platform** (OAuth consent screen):
   - *Branding*: app name and contact email
   - *Audience*: External, then **Publish app** (otherwise sign-in expires every 7 days)
   - *Data Access*: add scope `https://www.googleapis.com/auth/drive.file` (the app only sees the spreadsheet it creates)
   - *Clients*: create an **Android** client (package + SHA-1). For iPhone also create an **iOS** client (bundle ID `com.nhumark.openultima`) and put its client ID in `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID`.

Get your SHA-1 (debug build):

```bash
keytool -list -v -keystore android/app/debug.keystore -alias androiddebugkey -storepass android -keypass android | grep SHA1
```

A release build signed with another key needs that key's SHA-1 added to both the Maps key and the Android client.

### Health apps

- **Android:** Settings → Health apps → Health Connect. Writes steps (30-minute buckets), distance, calories, heart rate, resting heart rate, sleep stages and workouts with routes. Re-sent data replaces earlier records instead of duplicating them.
- **iPhone:** Settings → Health apps → Apple Health. Writes steps, distance, heart rate and workouts; days are added once they're over.

## Development

```bash
npm run typecheck   # tsc --noEmit
npm test            # node --test, ~3 s
```

Tests run the real protocol encoders/decoders and `UltimaBleManager` against simulated Bluetooth devices (`tests/fixtures/fakeBlePlx.ts`), plus storage, health-sync, workout-stats and Sheets-table suites. A source audit fails the build if network code appears outside the opt-in online modules (Google Sheets, Strava, OpenStreetMap tiles).

### Layout

```
App.tsx                     app root, services, deep links
index.ts                    entry; registers the background GPS task
src/app/                    screens, navigation, UI kit, shared map components
src/domains/
  audio/                    earbuds protocols (Jieli RCSP incl. auth, Bluetrum)
  watch/                    CRREPA watch protocol
  bluetooth/                UltimaBleManager, device controllers, live BLE adapter
  storage/                  OfflineStore, validators, exporters (JSON/CSV/GPX)
  healthSync/               Health Connect, Apple Health, Strava adapters + sync ledger
  sheets/                   Google Sheets export
  workouts/                 phone GPS recorder and track statistics
  calls/                    call audio routing (native module bridge)
modules/                    local Expo native modules (calls, keep-alive)
tests/                      node:test suites and fake BLE fixtures
```

Deep links (`com.nhumark.openultima://…`): `home`, `earbuds`, `health`, `settings`, `record`, `workout/<id>`, `sheets`, `health-apps`, `calls`, `packet-log`, and more — see `linking` in `App.tsx`.

## Privacy

- No analytics, ads or accounts.
- Network is used only for features you turn on: Google Sheets export, map tiles, and Strava (if configured).
- Health and workout data never leaves the phone otherwise.
